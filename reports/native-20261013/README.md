## 测量方法

```bash
poetry run python scripts/benchmark_native.py --output reports/native-20261013
```

服务器固定四个不同的物理核心，客户端使用另外四核。每路输入 10 秒，取官方
`hello_en.wav` 重复拼接，按 100 ms PCM 块不限速发送。模型、协议、后处理和两块
响应窗口一致；每档预热后测三轮。每路 2 秒短测低于 2× 实时或失败时，停止该后端
的正式测试及更高并发。本次所有后端均通过短测，45 个正式轮次全部零错误。

总吞吐 = 成功处理音频秒数 / 整轮 makespan；P95 是每轮各路 RPC 完成耗时的 P95。
下表报告三轮的中位数。测量包含 gRPC、IPC、原生预处理、模型和后处理。
资源与各轮耗时在 `raw.jsonl`，服务日志按后端与并发档分别保存。

本机是共享主机，使用独立进程、端口和 CPU affinity，但不能保证宿主机无其他负载。
首轮试测曾与导出矩阵测试重叠，已移到忽略的 `build/perf-trial-20261013`，不计入本报告。
本报告的正式复测期间没有同时运行本任务的构建或测试。

| 4 | 74.2× | 79.4× | 197.1× | 0.538 | 0.503 | 0.187 |
| 8 | 84.6× | 84.2× | 252.0× | 0.944 | 0.949 | 0.317 |

| 32 | 82.3× | 83.6× | 309.5× | 3.884 | 3.826 | 1.032 |

默认配置是 CPU 预算 4、worker 1、每 worker NCNN 线程 4；四 worker 配置是预算 4、
worker 4、每 worker 线程 1。默认配置在所有并发档通过预先定义的门槛：
吞吐不低于参考 90%，P95 不高于参考 110%。

四 worker 在 32 路约为参考吞吐的 3.76 倍，但单流完成耗时更高，因此没有自动改变默认配置。
该结果来自这组模型、音频、CPU 和协议配置，不能推广为所有设备或输入的固定收益。

## 线程与清理

模型加载、预热、推理和清理均在实际 worker 线程执行，避免在调用线程额外创建 OpenMP 池。
完整模型块的缓存通过整块复制更新；短块仍执行历史缓存修正，保持原有因果状态。

全部十个原生服务实例的最终指标均为 `sessions=0`、`pending=0`、`inflight_bytes=0`。
正常关闭后没有遗留本次服务父子进程；各实例的退出清理由基准 Server 生命周期检查。
`raw.jsonl` 中的 `native_metrics` 记录预处理、模型和后处理累计耗时，包含预热请求。
